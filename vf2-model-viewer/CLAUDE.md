# バーチャファイター2 モデルビューア — 作業メモ

PS2『SEGA AGES 2500 Vol.16 バーチャファイター2』（SLPM_625.47）のモデルを読む。
進め方の決まりは `../tobal1-model-viewer/CLAUDE.md`、教訓は `../CLAUDE.md` と同じ（返事は日本語、始める前に許可、絵を見ずに言わない）。

## いまの状態（dash.mjs がダッシュボードの先頭に出す。止めるときと再開するときに書き直す）

- 作業: セーブステート5つ（01〜05、PCSX2 v2.8.2、構えている場面）で、ゲームの命令の列から2人を組めた（pose.mjs）
- 頼んでいること: 投げ・倒れ・2色目の場面のセーブステート（あとで。いまの5つで先に進める）
- 次にやること: テクスチャと色（写しのパレット g_geo+0x40 とテクスチャ用メモリ g_geo+0xa040 で答え合わせ）→ ビューアのページ

## データの置き場所（リポジトリに入れない）

- イメージは Google ドライブから `src/disc/vf2.bin`（MODE2/2352、1トラック）に落とす。`src/disc/` と `src/out/` は .gitignore 済み
- `python3 iso.py disc/vf2.bin` で一覧、`iso.py disc/vf2.bin /BIN.CVM disc/x/BIN.CVM` で取り出し
- `python3 cvm.py disc/x/BIN.CVM disc/bin` で BIN.CVM（CRI ROFS。中は ISO9660）の 120 ファイルを取り出す
- `python3 cricmp.py disc/bin/*.CMP` で .CMP を展開して .dec を置く

## 分かっていること

各項目の頭の札（dash.mjs はこの札で色分けする）: 【確定】本体のコードで確かめた　【数字】全ファイルで数を数えて確かめた
【絵】描いて見て確かめた　【推測】まだ確かめていない　【×】試して合わなかった

- 【数字】`.CMP` は CRICMP 2.10。展開は本体 0x1547c0/0x154e80 を写した（`cricmp.py`・`cricmp.js`）。102 ファイル全部で展開後の大きさが頭の値と一致、JS と Python の出力も一致
- 【数字】OBJ ファイル（展開後）＝ [モデル数] + モデル×N。モデル＝[番号] + 塊×4（各 [長さ][中身]）。全ファイルの最後のバイトまで区切れる
  - 塊3 が面の記録 40B: +0 頭、+4 法線、+0x10 頂点A、+0x1c 頂点B（float）
  - 頭 bit0-1 = 形（0 終わり・1 四角・2 三角）、bit8-9 = つなぎ方。手元の2点 P0,P1 で面 (P0,P1,B,A)。
    つなぎ方 0=描かずに P0=A,P1=B、2=P0=A,P1=B、1=P1=A、3=P0=B（本体 0x1c9cc0）
  - 並べた頂点の向きとファイルの法線: AKI1・PAI1・WOL2 で 99.2% 同じ向き、STAGE1 は全部同じ（数字で確認）
- 【絵】描いた部品は手（握り・開き・指違いが多数）・腕・脚・足・胴らしい形に見える（絵で確認。どれが何かは推測）

## 写し（PCSX2 のセーブステート）

- 【確定】.p2s は zip（中身は zstd、形式番号 93）。`python3 p2s.py disc/states/x.p2s` で eeMemory.bin（主メモリ 32MB）・GS.bin・Screenshot.png などを取り出す。
  セーブステートは `src/disc/states/`（リポジトリに入れない）
- 【数字】主メモリの 0xf60000 付近（と 0xf68000 付近。2コマぶん交互）に、ジオメトライザへの命令の列がある。行列 0x05800000＋float×12、
  物体 0x00800000＋引数×4、焦点距離 0x04800000＋(600,600)。物体の4つ目の引数を g_objTbl（0x1fc8760、2人×5125 語。番号→読み込んだモデルの番地）で
  逆に引くと、5つの写しの全物体がモデル番号になる（01 は 904/904）
- 【絵】行列をカメラの座標とし、x'=x·m0+y·m3+z·m6+m9 …で置いて焦点 600 で写すと、5つとも2人が画面の写真と同じ姿勢の人の形になる（`node pose.mjs disc/states/01_akira_lau out/pose01.png`）
- 【数字】アキラの1コマ: 体 407〜414・416・417・421・422・2452・2454、手 217・259、帯などのひも 2・4・6・30・148・149・2498〜2500、影らしい平たい物 343〜354・415・418・424
- 【数字】命令の列は焦点距離の命令から始め、1つずつ読んで「終わり」（番号 15）で止める。引数の語数: 物体1=4・枠3=6・モード7=1・8=1・焦点9=2・光10=3・
  行列11=12・12=3・LOD22=1、bit31 の立った語は1語。5つの写しで知らない語なしに終わりまで読める。終わりの後ろには前のコマの古い命令が残っている
  （これを拾うと、パイの三つ編みがカメラの手前に浮くなどした）
- 【絵】枠の命令（番号3）の値は上位16bit=x・下位=y と読むと 496×384 の MODEL2 の画面で、中心はその真ん中。写真の絵の範囲（x 9〜630・y 34〜445）に
  引き伸ばして写すと、5つとも2人が写真にぴったり重なる
- 【数字】g_UnitMtxRob0/1Buf は 64B×16（向き3行＋位置、位置の w は NaN）。g_geo+0x40 からはパレット（16bit 色）

## 本体の作り（名前の表で確認。`python3 syms.py disc/x/SLPM_625.47 正規表現`）

- 【確定】本体には名前の表が残っている（6341個）。アーケードの i960 のプログラム（IC12_15.CMP、展開 512KB。戻り命令 0x0a000000 が 1756 個）を
  i960 のエミュレーター（i960Exec*）で動かし、ジオメトライザは PS2 側の代わりの処理（g_geo 0x135a000・m2epiExecGeoCmd・m2epiSetModel）、
  TGP の計算は PS2 の機械語に書き直したもの（cprMtx*・cprMot*）
- 【確定】面を読む divideModel 0x1c9cc0、展開 0x1547c0 など、上のアドレスは名前の表と一致
- 【推測】写しで見る所の候補: g_UnitMtxRob0Buf 0x1689d40・g_UnitMtxRob1Buf 0x1689940（各 0x400）、g_geo、g_objTbl 0x1fc8760

## テクスチャ（途中）

読めたこと
- 【数字】面の属性（塊0、8B＝16bit×4 の h0..h3）の位置は、面の頭 bit12-16（符号付き）×8B ずつ進む。UV（塊2、16bit u,v、1/8 画素）は
  描いた面ごとに四角 16B・三角 12B、つなぎ方0 の記録も最初の1つ以外は1つぶん進む（本体 0x1c6380）。6978 モデル全部で長さが一致
- 【推測】h0 bit14=テクスチャあり、bit0-2/3-5=大きさ（32..2048）、bit6/7=繰り返しの種類？ h1 下8bit=パレット？ h2=原点
  （x=(h2&63)*32、y=((h2>>6)&63)*32-1024、x≥1024 なら x-=1024,y+=1024、bit12=ページ）
- 【確定】テクスチャ用メモリは g_geo+0xa040。512KB（1024×512 の 4bit、1行 512B が2ページ）をそのまま GS に送る（TBP 0x3800、PSMT4、TBW 16）
- 【確定】TEX_ROB.MRG は CRICMP×11（各 98304B）。1人ぶんを sysGeoWriteRobTex が 128B×768行、行の間隔 256B で書く（1P はページ1）
- 【推測】GS の UV（通常時）: s=2(x+u/8)/2048、t=(1024*ページ+(y+v/8)/2)/2048（TW=TH=1024 と読んだ）

合っていないこと
- 【×】上の読みで貼っても絵にならない（sheet.mjs の ROBTEX/TEXY で試せる。11 個どれも×）。TEX_ROB の何番が誰かも未確定
- 【推測】パレットの場所はまだ探していない（h1・h3 と m2epiUpdatePolygonPalette が手がかり）
- 【推測】写しの GS のメモリ（VRAM）が来れば、実際に置かれたシートとパレットで答え合わせできる
