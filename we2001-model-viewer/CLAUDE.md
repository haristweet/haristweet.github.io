# Jリーグ実況ウイニングイレブン2001 モデルビューア — 作業メモ

進め方の決まりは `../tobal1-model-viewer/CLAUDE.md`、教訓は `../CLAUDE.md` と同じ（返事は日本語、始める前に許可、絵を見ずに言わない）。

## 選手の見た目（v0.2.0 で読んだもの。番地は本体 SLPM_868.35、SELECT.BIN は 0x8007a558 に読む）

- 【確定・数字】チーム名: SELECT.BIN 0x3b1e0 からの番地の表（43）。選手名: J は 0x439a0 からの表（728＝28×26）、34〜40 は本体 0x80052bc8＋t×260＋i×10
- 【確定・数字】選手の値（12 バイト A,B,C）: SELECT.BIN 0x26e28＋(t×26＋i)×12（J）、0x29048＋((t−34)×26＋i)×12（SELECT の 0x80087060）。試合の前に本体 0x80079948 へ写す
  髪型＝本体 0x800516e8 の表[(A>>4)&31]（0〜15、頭の表の番号＝髪型×2＋ひげ、0x8001b640）・髪の色＝(A>>9)&15・顔＝(A>>13)&15（5 以上でひげ）・色 2＝(A>>17)&7・肌＝B&3・スパイク＝(C>>27)&7
- 【確定・絵】色の表の位置の書き換え（0x800125b4〜）: 行 480〜483 の x＝0 は肌の行に、1〜8 は髪の色＋1、9〜 は色 2＋9。行 484 はスパイク。486/488 は 1P、487/489＋ページ 640 は 2P
- 【確定・絵】顔の UV（0x800112a4、分岐表 0x8004f5a0・0x8004f5e0）: 面の v0 の下 4 ビットが 0/12 なら顔×16、14 以上なら髪型×16（髪型 9 未満）
- 【確定・絵】背番号: 本体 0x80055e5c＋t×26＋i の値＋1。組み立ては 0x8001f204（欄、背景 598,262／キーパー 630,262、数字 608＋3d,324）、貼る UV は 0x80011184（胴の 3・15 番目の面）
- 【推測・絵】チーム t のユニフォームは TEX_t（0〜40 の色を見比べた範囲で合う。ゲームの対応表は見つけていない）。キーパー＝A&15＝0（28 チームの 1 人目が全部 0）

- 【確定】選手には光を当てない（0x80011444 に光の命令が無く、色は 0x7f7f7f 固定。0x8001235c）。画面の色＝テクスチャの色（数字）

- 【確定】キーパーの色の表は札 4/5 をユニフォーム（札 1/3）と別に選ぶ（SELECT.BIN 0x8008eea4・0x8008eee8）
- 確かめの台本の注意: Playwright の selectOption("1") は表示の文字にも当たる。数字の選択肢は {value:"1"} で選ぶ

## 集合写真（v0.3.0。ENTER.BIN は 0x8007a558 に読む）

- 【確定・絵】ENTER.BIN 0xfad8 に 16 個の動きの表（0＝入場の歩き 36 コマ、2〜15＝1 コマの姿勢。7＝GK の腕組み、6＝腕組み、2＝直立、8〜12＝しゃがむ）。コマは ANIME.BIN と同じ形
- 【確定・絵】0x8007c76c: 並び i（0〜10）の立ち位置＝0xfb18＋側×66＋i×6 の (x,z) に +3072・+4096（2P は x の符号を反対）、姿勢は乱数（photo.js の wePhotoRandomPose）。表の 3 つ目は決まった姿勢＋256
- 【確定・絵】カメラ: 場面 64（2P は 65）＝位置 (−178,−320,−3633)・見る点 (−2096,−256,−2609)・奥行き 603。48 コマ目から (−1280,−384,−4554)・(−1280,−382,−416) へ毎コマ寄せる（0x80080538、混ぜる関数 0x8002585c）。画面は 512×240（0x8001aea4）
- 【推測】スタメン＝選手の表の 0〜10 番目。体は GK＝組 4、ほか＝組 6。選手は回さず −Z（カメラ）を向く

## 分かったこと（本体の番地は SLPM_868.35、読み込み番地 0x80010000、ファイルの 0x800 から）

- 【確定・絵】MODEL.BIN（0x8016ab80 に読む）は PS1 標準の TMD が 104 個。面は全部モードどおりに読める（`tmd.js`）。0,1＝球、残りは選手の部品
- 【確定・絵】MODEL.BIN の先頭 18 個の番地が「組」。組＝(型,番地) の並び、0xff で終わり。型 0x80＝頭（0x68 の 64 個の表から選ぶ。偶数ひげなし・奇数ひげあり）、2＝部品。
  並びは 頭・胴・腕 4・脚（もも・すね・足）×2 の 12。組 6＝フィールドの選手、組 4＝キーパー（手袋）
- 【確定・絵】ANIME.BIN（0x8017ee80）。先頭は動きの番号→コマの番地の並び（0x80026c74）。1 コマ＝部品ごとに 8 バイト。
  読み方は 0x80011ba0〜0x80011dbc（`anim.js` に書いた）。部品ごとの回転（RotMatrix、0x8003c560）と位置を、親子をたどらず選手全体の行列に掛ける（0x80011fc8）
- 【確定・数字と絵】回転の掛け方は Rz·Ry·Rx。最初 Rx·Ry·Rz と思い込んで、曲げた脚が外れた（第一段階の絵は立ち姿もずれていた）。
  48 通りを試し、全部の動きで「親に固定した点＝子に固定した点」の当てはめのずれが最小のもの（膝・足首・肩・ひじ・首で二乗平均 1 未満）。膝はももの y＝88、すねの y＝−57（すねの部品の上の端）。股関節だけはずれが大きい（5.8）
- 【確定・絵】テクスチャの札（0x8001c8d8）: 型 9＝そのまま、10＝圧縮（0x8001cae8、`weUnlz`）。TEX_xx と DAT2D は 0x800f0000 に読む。
  DAT2D は 2 つの並び（絵 23 枚、色の表）で、顔・肌・髪（4 ビット、VRAM 512,256 など）。TEX_xx はユニフォーム（8 ビット、576,256／576,384、色の表 486・488）
- 【数字】場面ごとのプログラム（GAME.BIN など）の読み込み番地は `ovl.py` で出せる（GAME.BIN＝0x8007a558）
- 道具: `dis.mjs`（tobal1 の mips.js で逆アセンブル、GTE も出る）・`mipsgrep.py`（命令を正規表現で探す）・`mipsdis.py --ref`（lui＋即値で作る番地を探す）
