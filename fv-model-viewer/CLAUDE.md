# ファイティングバイパーズ モデルビューア — 作業メモ

PS2『SEGA AGES 2500 Vol.19 ファイティングバイパーズ』（SLPM_626.06）のモデルを読む。
進め方の決まりは `../tobal1-model-viewer/CLAUDE.md`、教訓は `../CLAUDE.md` と同じ（返事は日本語、始める前に許可、絵を見ずに言わない）。
PS2 版 VF2（`../vf2-model-viewer/`）と同じ作りの移植なので、VF2 で分かったことを先に当てて、合うかを確かめながら進める。

## いまの状態

- 作業: ディスクと写し 4 つで、命令の列から 2 人と背景を組み、写真に重なるところまで（`node src/pose.mjs`。色・テクスチャはまだ）
- 写し（2026-09-27、ユーザーから）: grace1P_picky1P_round1・bahn1P_honey1P_tower・raxel1P_jane1P_tower・tokio1P_sanman1P_tower（どれも構え）。
  ユーザーは基本ソフトウェア描画で撮っている（GS.bin にゲームが描いた画面が入る。`node src/gsframe.mjs 写し out/gs.png`）
- 頼みたいこと: 同じキャラ同士（2P の色）・投げ・ダウン・鎧が壊れた所、ほかのキャラ（マーラー・ピッキー以外の隠れキャラなど）
- 次にやること: 色（色 RAM・色の変換表・パレットの置き場所を探す）→ テクスチャ → ページ → 技（VF2 の motion.js を当てる）

## データの置き場所（リポジトリに入れない。`src/.gitignore` で disc/・out/・*.chd などを外す）

- イメージは Google ドライブの CHD（`src/disc/fv.chd`）。`node` で tobal1 の disc.js（ChdDisc）を使って `src/disc/fv.bin`（2352B/セクタ）に書き出した
- `python3 iso.py disc/fv.bin` で一覧（ADXJ.CVM・BIN.CVM・SLPM_626.06 など。VF2 と同じ並び）、`python3 iso.py disc/fv.bin /BIN.CVM disc/x/BIN.CVM`
- `python3 cvm.py disc/x/BIN.CVM disc/bin` で 179 ファイル、`python3 cricmp.py disc/bin/*.CMP` で .dec（103 ファイル、大きさが全部合う）
- 写しは `src/disc/states/`、`python3 p2s.py disc/states/x.p2s` で展開
- iso.py・cvm.py・cricmp.py/js・obj.js・p2s.py・png.mjs・raster.js・tex.js・sheet.mjs は VF2 の道具をそのまま写したもの（中の説明の番地は VF2 の本体のもの）

## 分かっていること

各項目の頭の札: 【確定】本体のコードで確かめた　【数字】全ファイルで数を数えて確かめた　【絵】描いて見て確かめた　【推測】まだ確かめていない　【×】試して合わなかった

- 【数字】ディスクの BIN.CVM の中に、アーケードのロムが入っている: ROM_CODE1（展開 512KB。i960 の戻り命令 0x0a000000 が 1956 個）・ROM_CODE2（1MB）・
  ROM_DATA（16MB）・ROM_POL（12MB）・ROM_TEX（8MB）・ROM_EP1/2（各 1MB）。どれが何かは【推測】（名前から: 形・テクスチャ・データ）
- 【数字】本体の名前の表は消されている（.symtab が空。VF2 は 6341 個残っていた）。文字列には VF2 と同じ M2EPOL などが残る
- 【数字】計算用チップ（アーケードは Model 2B の SHARC）の代わりの関数の表が本体の 0x23fc20 にある（16B ずつ 112 個。VF2 は 0x207a50 に 112 個）。
  引数の語数・返すバイト数が VF2 と同じものが 97/112
- 【数字】モデルのファイル（OBJ_*.CMP を展開したもの）は VF2 と同じ形式: 57 ファイルとも最後のバイトまで区切れ、面の読めないモデルは 0（VF2 の obj.js）
- 【絵】OBJ_ROB00 の部品は手・腕・脚・胴・頭らしい形。1849〜1922 はお椀の形が段々と粉々になる並び（鎧が壊れる所？【推測】）
- 【数字】描く命令の列: 主メモリの 0x1288000 付近から（焦点距離の命令 0x04800000 の値は 480。VF2 は 600）、0x8000 おきに同じ形の列がいくつもある。
  VF2 と同じ番号（物体1・枠3・モード7・焦点9・光10・行列11・LOD22）に加え、4＝[番地][語数 n][n 語]・13 と 16＝1 語、で 4 つの写しとも終わり（15）まで読める
- 【数字】番号 → 読み込んだモデルの番地の表は 0x1f834f0（2 人 × 5413 語。VF2 は 0x1fc8760 に 2 人 × 5125 語）。表の番地の先の、読み込み済みのモデルの中に、
  ファイルのその番号のモデルの頂点（小数 3 つ）がある: 4 つの写しで前半 1994/2000、後半 625/625。読み込み済みのモデルの頭は VF2 と同じ（…00000060 … 01000030）
- 【絵】行列をカメラの座標とし、焦点 480 で写す（VF2 と同じく x は 622/496、y は 412/384 倍して 640×480 の真ん中へ）と、4 つの写しとも 2 人と背景（柵・建物・ヘリコプター・ロープ）が写真に重なる
- 【絵】GS.bin の画面は VF2 と同じ読み方（頭 0x1a9 の後ろに 4MB、PSMCT32・幅 512、FBP 0 と 0x80）で、続いた2コマ（タイマー 26・25）が出る（grace）
- 【数字】キャラのファイル（写しで描いた番号をいちばん多く含むもの）: ROB00 ジェーン・ROB01 グレース・ROB02 ハニー・ROB03 トキオ・ROB04 バーン・ROB05 ピッキー・ROB06 ラクセル・ROB07 サンマン。
  ステージ: STG02＝round1（グレース対ピッキー）、STG08＝塔（ヘリコプター）。OBJ_COMMON からも 28〜32 部品（影など？【推測】）
