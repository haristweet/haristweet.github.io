# トバルNo.1 モデルビューア — 作業メモ

PS1『トバルNo.1』のキャラクターを、ディスクイメージ（＋対戦中の RAM/VRAM ダンプ）から
ブラウザで表示する。公開は `index.html` 1枚（GitHub Pages）。経緯は CHANGELOG.md（長いので必要な所だけ grep）。

## 進め方（ユーザーとの決まり）

- 返事は日本語。**処理を始める前に、何をするか短く示して許可をもらう**（週の使用上限が近いため）
- 許可が出たら「作る → 試験 → `index.html` を置き換え → コミット → 作業ブランチに push →
  main へ fast-forward で合わせて push」まで任されている。PR は頼まれない限り作らない
- 絵を見ずに「人の形になった」などと言わない。確かめた範囲だけを言う（何度も外した）
- メモリやファイルの解析はこちらのコードでやる。ユーザーに手作業で読ませない
- 変更履歴（CHANGELOG.md）とコミットメッセージは短く（数行）。版は `src/app.js` の `VERSION`

## 組み立てと試験

```
cd tobal1-model-viewer/src
sh check.sh          # 偽の試験データを作る → 組み立て → 単体試験（node test.mjs）→ ../index.html を置く
node browser.mjs     # ブラウザで確認（Playwright）。dump3.bin / vram.bin があれば写しの確認もする
```

- ソースは `src/*.js` と `head.html`。`assemble.py` が決まった順に連結して `index.html` を作る
- `test.mjs` は主要な .js を1つの関数に連結して実行し、**最上位の名前を全部グローバルに出す**
  （一覧を手で書かない）。オフラインで絵を描く道具を作るときも同じやり方で読み込める
- `dump3.bin`（対戦中の RAM 2MB）と `vram.bin`（VRAM 1MB）はゲームの写しなので**リポジトリに入れない**。
  必要なときはユーザーにアップロードしてもらい `src/` に置く（.gitignore 済み）

## 分かっていること（確定）

モデル（`model1.js`）
- ファイル先頭の署名 0x90000000。部品は「面/頂点/法線/色」の4つの位置を持つ。本体1＋差し替えの組（4/4/2）
- 面の命令: 8=三角+法線 20B、9=四角+法線 24B、10=三角 12B、11=四角 16B、12=三角+法線 20B（テクスチャ）、
  13=四角+法線 24B（テクスチャ）、14=三角 12B・15=四角 16B（テクスチャ、法線なし）。命令5 で区切り（＝骨）が1つ進む。区切りは1から、骨は0から（ずらし -1）
- 頂点の骨は「その頂点を入れた区切り」（面の区切りではない）
- 色の語は命令の列を歩きながら数える: 命令8・9=1語、12・13=4語（語0=白、語1〜=u,v＋CLUT/ページ）、
  10・11=0語（頂点ごとの色を使う）、14・15=3語（u,v だけ。色は頂点ごと）、命令2=入れた頂点1つにつき1語。写し6組・12体の全部品でバイト数ぴったり
- テクスチャは 4bit。ページ 0x1e→VRAM(896,256)（1P）、0x1f→(960,256)（2P）
- 差し替えの組: 組1=右手4種、組2=左手4種（Z の鏡像）、組3=顔の貼りもの2種（目・眉・傷。表情違い）。
  本体に手は無い。貼りものは 6 押し出す。ファイルの法線は内向きなので、向きは区切りの中心から外へ（`t1PushSign`）、頂点ごとに共有する面の法線を平均して押す
- 差し替え部品の付く骨: 部品の頂点がいちばん重なる本体の区切り（`t1SlotAttach`）。
  RAM の描く命令の並び（1P は 0x801E69C4〜: `6, 行列, 行列, 0x10, 0, 部品…`）と6つとも一致
  （1P 右手30 左手36 顔39／2P 右手24 左手30 顔33）。どの手の形を使っているか（`0x10, 0`）は未解明

RAM ダンプ（`mem.js`）
- キャラクター1体の入れものは 0x1E48 間隔。1P の表A=0x801F0584、B=0x801F0484、C=0x801F0684（2P は＋0x1E48）
- 表C[0] ＝ モデル先頭＋0x3C。骨の本数＝本体の命令5 の回数（1P 40・2P 34）
- 骨は表B のポインタが指す 32B の行列（回転 4096=1.0＋移動）。変換は `R·v+T`、Y がそのまま上（`T1_UP_WORLD=0`）
- 写しの骨は、本体の命令5 の回数と本数が合うモデルにだけ当てる（`t1BonesFit`）
- dump3: 1P＝イール・ゴガ（ディスク #157 / sector 9742）、2P＝チュージ（sector 未確定）
- dump4: 1P＝オライムス（骨34）、2P＝ホム（骨26）。表を指す語が 0 だったので、いつもの場所を直に読む
- 写し `dump_01`〜`04`（1P・2P）: チュージ・グリン／オライムス・イール・ゴガ／エポン・マリー／ホム・フェイ。
  全部品の色の語数が並びとぴったり合う（v4.48.0）
  `dump_05`: エポン・グリン（2色目）、`dump_06`: ホム・マリー（2色目）。どちらもコードの直しなしで出た。
  `dump_07`: オライムス・フェイ（2色目）。これで主要8キャラ×2色が揃い、16体ともコードの直しなしで出る
- 正面の向きは骨0 の (0,1,1) を水平にしたもの（`t1FrontYaw`）。1P は +X、2P は −X を向いている
- 骨の組はカメラ前（ワールド）が表B の指す先の 0xF60 手前。回転の行列として読めればそちらを使う（ポーズでは決めない。20体で確認）

保存（`app.js` の saveRamChars / selectSaved）
- 写しの人は IndexedDB（tobal1-viewer / chars）に保存できる。モデル・骨（memCharBones の結果）・VRAM 生 1MB。
  選ぶと写しの人と同じ形にして selectRamChar で描く

3Dプリント（`print.js` が中身、`printui.js` が画面）
- 升目 → 太らせ（最小の厚み）→ 外から塗りつぶし → 台座・中空 → 四面体で表面を作り直す。必ず閉じる（printCheck で辺を数える）
- 出力は mm。STL は Z 上、3MF は点ごとの色（5bit に丸める）。SOLIZE は STL/3MF/WRL・1ファイル 20MB まで
- 中空は液抜きの穴を開けていない
- テクスチャで塗る 3MF（printBake）: 面1枚に 3×3 画素、いちばん近い元の面の色を写す。塗るのに 20 秒ほどかかる
- 元の形の glb（printAtlas / printGLB）: テクスチャはページ＋パレットの組ごとに VRAM から切り出して1枚に。メートル・Y 上
